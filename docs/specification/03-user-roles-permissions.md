# 03 · Roles and object permissions

Active roles: PASSENGER, DRIVER and ADMIN. Registration grants PASSENGER. Verified active users may self-enable DRIVER onboarding; the role does not imply qualification. ADMIN is operator-granted, never public input. OWNER is a retired product role in this release: vehicle ownership is immutable vehicles.owner_id -> users.id. The completed foundation's role enum may still contain OWNER until the first contract-alignment implementation task removes it; no active endpoint grants it.

Passenger reads/edits only own profile, personal vehicles, bookings and seat participation. Assigned driver sees own booking decisions and trip work. Carpool host reads own participant display names/seat counts and operates own ride. Public users see approved driver listings and safe published carpool/vehicle summaries only. Full vehicle registration, contact information, license evidence and passenger roster are never public.

Every endpoint checks current active account, required capability, qualification and object relationship on the server. Foreign private objects return404; role denial403; invalid session401. Administrator operations verify current ADMIN, prevent self/last-admin suspension, require reasons for sensitive writes and append audit. Administrator approval of own evidence is forbidden. Same-account passenger/host/driver roles never permit self-hiring or joining one's own carpool. Account suspension revokes sessions and resolves unstarted commitments transactionally; active physical use remains an incident until resolved.
