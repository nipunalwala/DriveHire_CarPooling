## Transaction lock protocol

Use READ COMMITTED plus explicit row locks and database constraints; correctness must not depend on an ORM default isolation feature. Determine affected account IDs, driver IDs, vehicle IDs, booking/carpool IDs before locking; acquire user rows ordered UUID, then driver_profiles ordered UUID, then vehicles ordered UUID, then booking/carpool aggregate rows ordered UUID, then child request/decision rows ordered UUID. Read dependencies, lock, re-read and verify unchanged; retry discovery if the set changed. All resource and eligibility mutations (including suspension, archival, blocks and verification) follow this protocol. Seat-only operations lock relevant user rows, then carpool row, then request; never acquire a resource lock later. Suspension pre-discovers all affected aggregates, locks resource set, rechecks before writes; creates cannot race because user/resource locks are shared protocol.

Persist domain writes, histories, admin audit, idempotency result in the same DB transaction; authentication challenge creation also enqueues its email job atomically. No SMTP/file scan/HTTP call inside locks. Use bounded3-attempt jittered retry only for deadlock40P01/serialization40001; preserve key and request hash across retry. Map exclusion23P01 to409 RESOURCE_CONFLICT, unique23505 to context-specific409. If an intermediate failure occurs, roll back all related writes. A bounded retry exhaustion returns503 RETRYABLE_TRANSACTION. A failed business precondition is not retried automatically.

## Cross-row invariants

Resource reservation source is exactly one booking/carpool/block; resource exactly one driver/vehicle. Trip belongs to exactly one booking/carpool. Each live booking/carpool must have exactly two live reservations matching its actual resources. Seat count bounds are DB CHECK; sum equality is maintained by single locked service and reconciliation read. Aggregate states/history agree. Tests assert these across cancellation, expiry, suspension and worker replay. DB triggers/constraints enforce immutable ownership, append-only history and audit where appropriate; repositories cannot bypass domain service authorization.

Only DRIVER_HIRE and INSTANT join are active. BR22 ratings/reviews is deferred. No owner/fleet workflow or domain notification requirement survives from the archived baseline.
