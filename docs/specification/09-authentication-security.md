# 09 · Authentication Security

Status: proposed implementation baseline; implementation requires separate human approval.

## Passwords, OTP and reset
Argon2id minimum memory19456KiB,timeCost2,parallelism1, random salt; calibrate API target hash time150–400ms under documented deployment hardware without going below minimum. Password12..128 Unicode characters, at least one non-whitespace, no arbitrary composition policy; never truncate, log or normalize password bytes. Normalize email only. Rehash on successful login when configured parameters increase. Use constant-time challenge digest comparison and dummy password verification for unknown email to reduce enumeration.

Verification OTP: cryptographic random6digits, valid10min, max5 failed attempts/challenge; sixth verification never succeeds. HMAC-SHA256 with secret pepper because6digit space is small; bind user,purpose,revision. One live challenge/user/purpose; invalidate on resend/reset. Resend>=60s, max5/hour/email plus IP quotas. Increment attempts under row lock even if code is wrong, commit attempt failure independently of response error handling. Email verification consumes challenge in same transaction as user verified_at update.

Reset token256random bits base64url, store SHA256 digest;15min expiry, one live token, single use. Return generic202 for request with roughly comparable processing; no email/account reveal. New password update, challenge consumption, family revocation and tokenVersion increment are atomic. Reset tokens in URL fragment read client-side then POSTed, scrub via history.replaceState before analytics; never third-party analytics on auth pages. Sensitive email payload encrypted in outbox, scrub after delivery; app logs only safe event IDs.

## Access and refresh
Access JWT15min with aud/iss/exp/iat/jti/sub/sid/tokenVersion, RS256 with key ID and explicit algorithm allowlist. Keys outside source, rotate with previous public key overlap at least15min; fail expired/incorrect issuer/audience/skew>30s. Token kept in memory, never local/session storage/URL. Each protected request loads current account status/role/tokenVersion and refresh family revocation; immediate suspension/logout invalidates old access. Cache this auth check only if invalidation is strongly propagated; initial implementation uses DB each request.

Refresh cookie random256bits, SHA256 hash at rest, HttpOnly, Secure except localhost, SameSite=Strict, Path=/api/v1/auth, fixed absolute family expiry30days; each successor expires min(now+7days,absolute family expiry). No sliding extension beyond30days. Lock token and family on rotation, consume old, issue one child; replay of consumed/revoked token revokes family and rejects401 including any successor. Unknown token401. Keep consumed hashes until family expiry+7d.

Browser refresh coordinator serializes within a tab and across tabs using Web Locks where supported plus BroadcastChannel; transmit short-lived access token in-memory channel only. Fallback elect one refresh owner using a short nonsecret localStorage lease, never token persistence. Duplicate refresh requests must not be fired concurrently. If response lost after rotation, strict replay policy may require login; do not weaken theft detection with undocumented grace. Retry original request once only. Logout always clears cookie exact same scope; active sessions list exposes IDs/dates only.

## Rate limits and abuse budgets
Use PostgreSQL atomic rate_limit_buckets so replicas share budgets; hash address/IP keys with separate pepper; cleanup expired buckets. Trusted reverse-proxy hops explicitly configured; do not trust arbitrary X-Forwarded-For. Login10/min/IP plus10/15min/address, register5/hour/IP, OTP verify10/min/IP and5/challenge, resend5/hour/address plus10/hour/IP, reset5/hour/address and10/hour/IP, refresh30/min/family+60/min/IP, general protected writes60/min/user, uploads20/hour/user, searches120/min/IP, admin reads300/min/admin. Return429 Retry-After seconds. Apply before expensive hash/scan work. Avoid permanent lockout attackers can exploit; timed buckets and support recovery.

## Authorization and input boundaries
Zod strict bodies, typed UUID params and allowlisted query filters; mass assignment forbidden. Backend role union plus object association and active eligibility; client-submitted ownerId,role,verified,total,status ignored by strict rejection. Parameterized Prisma/raw SQL only. Admin web routes are not sufficient. CSRF: bearer-only business routes; cookie refresh/logout Origin allowlist+JSON content type+SameSite. CORS exact scheme/host/port allowlist with credentials, never wildcard/null; one-origin staging/prod preferred. HSTS production, CSP default-src self with minimal image/media sources, frame-ancestors none, nosniff, Referrer-Policy strict-origin-when-cross-origin, safe URL encoding. Helmet defaults audited. No raw review HTML, no markdown execution, no arbitrary redirectUrl; returnTo same-origin relative allowlist.

## Uploads and secrets
5MiB max/file; bounded multipart fields; magic bytes and decoder verify JPEG/PNG/WebP/PDF; reject SVG/HTML/executables/polyglot images when decoder fails; re-encode image and strip EXIF. Do not fetch user-supplied remote file URLs (SSRF). Private quarantine, random UUID filenames, no path names from client, scanner fail closed, signed/authorized short-lived image read only after CLEAN. Private PDFs attachment with no-store, nosniff and restrictive content disposition; no public index. Production encryption at rest plus application envelope encryption for license/registration values; separate HMAC digest provides normalized uniqueness. Key version recorded for rotation, never logged. Environment examples contain names and dummy nonsecret markers only.

## Audit, dependency and operational controls
Append actor/action/subject/reason/requestId/safe before/after in same transaction as privileged mutation. Audit sensitive document/admin user detail reads. Runtime DB role cannot update/delete audit/history or DDL; migrations run separate role. Seed command refuses NODE_ENV=production. Secret scan tracked current files; history scan separately before public visibility change. Lock dependency versions; assess advisories with remediation evidence; no blind forced major upgrades. CI tokens scoped to read/build unless deploy job approved. Backups encrypted and restore-tested. Threat cases: broken object authorization, stale role/session, OTP brute force, refresh replay, insecure direct upload, SQL/XSS/CSRF/SSRF, duplicate state mutation, resource/seat race, notification loss and operator misuse.
