# 11 · Driver-hiring lifecycle

Only DRIVER_HIRE. Requester supplies an owned approved vehicle; chosen external approved driver has covering availability and a current rate. Quote10minutes; price=ceil(seconds/3600)*driver hourly rate in integer paise, bounded100000000. Quote/create recheck current versions, approval, resources, ownership and time. Lead60minutes; booking duration1..720hours; horizon180days; origin/destination and passenger/capacity rules remain validated. No self-hire or borrowing another user's vehicle.

Creation locks accounts/resources, consumes own unexpired quote, creates PENDING booking, exactly one DRIVER decision, SCHEDULED trip and driver+vehicle reservations in one transaction. expires_at=min(created_at+30min,starts_at-15min). Acceptance by assigned driver before deadline confirms booking and assigns trip; rejection records reason, terminalizes trip and releases reservations. Missing/stale/foreign decisions cannot mutate state. No owner consent or replacement endpoint. Cancel then new quote/request to change resources.

Passenger may cancel pending before expiry, confirmed>=15min before scheduled start. Driver may cancel before actual start with reason; administrator may override pre-start cutoff with reason. Rejection/cancellation/expiry preserve histories and release exactly once. Accepted requests still revalidate documents/qualification before start. Trip driver/admin transitions ASSIGNED->STARTED->IN_TRANSIT->COMPLETED; STARTED or IN_TRANSIT may become FAILED with reason. Synchronize parent terminal status and releases transactionally. Clock never completes an active trip; expired unstarted ASSIGNED trip at starts_at+30min synchronizes EXPIRED parent. Active overrun retains physical-use guard and flags administrator incident.

Start window is [starts_at-15min,starts_at+30min]. Lock and check no other active trip on either resource, even when reservation times are adjacent. Record immutable trip history for booking/trip changes with actor and reason. No domain notification enqueue; participants reload state in app. Prove accept-vs-expire/cancel races, quote changes, rollback after reservation failure, idempotent create replay, authorization, active overrun and exact history/release effects.
