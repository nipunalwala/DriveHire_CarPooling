# 15 · Testing strategy

Keep existing foundation tests green. Unit tests cover validators/pure rules; contract tests exercise real Express handlers/envelopes; integration tests run actual dedicated PostgreSQL, migrations, privileges, transactions and concurrent connections. UI component tests verify interaction and recovery; browser E2E runs real API/database flows, not fake-success routes. No test solely mirrors implementation or greps source to prove behavior.

Each feature task follows RED->GREEN with named failure/assertion evidence; milestone handoff records commands/results and independent review findings. Core race suites use separate connections and synchronization barriers: refresh replay, resource conflict, final seat, consent-vs-expiry/cancel, join-vs-start/cancel, suspension-vs-new work and worker replay. Assert persisted rows/history/resource counts after success, rejection and rollback. Test database guard requires dedicated drivehire_test and explicit local55433 or database-test5432 without connection options; never use dev/retired DB.

Commands remain npm test, typecheck, lint, format:check, docs:check and build; dedicated services enable test:integration/infra:check. Milestone02 replaces deliberately unavailable Prisma/constraint scripts with actual suites. Milestone03 establishes real browser runner and first auth E2E; later milestones add journeys. No future-suite exit2 is a pass. Full security/keyboard/contrast/responsive audit and backup/restore rehearsal close milestone08. Production deployment, load SLA or remote CI cannot be claimed from local equivalents.
