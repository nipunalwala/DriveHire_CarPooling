# Phased roadmap and critical path

The 24 implementation phases run after separate explicit implementation approval. Each finishes with a working, tested vertical or platform slice and a handoff; no phase may declare a future dependency “done” through a stub. The conservative default order is sequential so a fresh agent inherits stable contracts. Independent UI work may be parallelized only after relevant backend and design-system phase handoffs, using isolated worktrees and one owner for shared contracts/migrations.

## Dependency notes
Phase02 provisions schema/constraints before any persistent feature. Phase03 establishes current-account authentication and email;04 adds roles;05 and06 establish provider qualification. Phase07 uses both providers and shared resource holds. Phase08 reuses those holds for carpools. Phase09 completes trips,10 reviews,11 durable in-app delivery,12 full admin. Phase13 sets shared UI system,14 public discovery,15 auth UI,16–19 role dashboards,20 integration,21 security,22 quality,23 operations,24 final audit. Initial domain services may enqueue future notification event types, but Phase11 registers their real in-app handlers and must verify earlier producer paths. Before Phase11 these events remain pending by channel and are never silently marked delivered. Expiry services for nonexistent future aggregates are added in the owning phase, not stubbed.

## Generated image and Impeccable gates
Phase13 adopts the Impeccable design brief/tokens; Phase14 generates original raster imagery for public pages and places final selected assets under `apps/web/public/images/generated/` with prompt/provenance manifest, dimensions and alt text. Phase17–19 may generate distinct explanatory decorative assets only if they help task comprehension; no fake driver/owner/vehicle identity, document, testimonial or listing photo. User-uploaded real vehicle media stays separate. The image generation skill's built-in tool is preferred at execution; generated project assets are copied into workspace and committed, never referenced solely from a tool cache. No generated image is required in this planning-only commit.

## Risks on critical path
PostgreSQL extension availability and ORM migration compatibility before02; scanner/SMTP/durable storage before qualification launch; cross-service reservations and seat concurrency before UI claims of availability; domain outbox replay before reliable notifications; production host/credentials and operating-policy choices before launch. Each risk has owner/proof in [risk analysis](../specification/17-risk-analysis.md).
