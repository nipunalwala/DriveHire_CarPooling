# Generated project image policy (planning)

The project will use original generated raster images for public explanatory and marketing surfaces. Phase14 is the first image-generation phase; this planning commit contains no app asset. Use the imagegen skill and built-in generation tool at execution time. Generate images against the approved Impeccable visual direction, review the actual output, choose only content that communicates a real service concept, copy final selected files into `apps/web/public/images/generated/` and commit. The tool cache is not a project asset. Never hotlink the generated cache or publish images created only for preview.

For each final asset record: filename; page/placement; full prompt; tool/date; selected dimensions and format; composition/visual rationale; whether decorative or exact alt text; color/contrast and responsive crop; original source generated filename; any edit/derivative conversion; explicit “illustrative generated image” status. Record output provenance in this manifest during Phase14 and update with later phases. No generated images of real drivers, owners, vehicle listings, licenses, registration, insurance, customer testimonials, verified badges or operational reports. Listings show actual authorized clean owner-uploaded media. If depicting people for a generic editorial image, avoid implying they are platform users, providers or verified staff; captions identify illustration when otherwise ambiguous. Do not let asset generation alter factual product copy.

Design review at Phase13 chooses placements and composition needs before image generation. At Phase14 generate distinct scene prompts per asset, inspect desktop/mobile crops, optimize for page performance and compare with Impeccable craft/QA guidance. Keep meaningful CSS/SVG icons native. If an image fails generation, report the limitation; do not substitute an unapproved remote source or pretend it was generated. The original prompt and provenance are documentation; no image API key is committed.
